## Пререквезиты

Целью было запустить какую-нибудь ВМ; В целом, это не сильно сложно, обычно, я
делаю это вот так:
```bash
sudo qemu-system-aarch64 \
  -machine virt,virtualization=on \
  -accel hvf \
  -cpu host \
  -m 16G \
  -smp 8 \
  -drive if=none,id=hd0,file=mnt/drive.img,format=raw,discard=unmap \
  -device virtio-blk-pci,drive=hd0,serial=dummyserial,discard=on \
  -drive if=pflash,format=raw,readonly=on,file=/opt/homebrew/Cellar/qemu/11.1.3/share/qemu/edk2-aarch64-code.fd \
  -drive if=pflash,format=raw,file=vars.fd \
  -display none \
  -serial mon:stdio \
  -nic vmnet-shared,model=virtio-net-pci \
  -boot menu=on,splash-time=0
```

Иногда меняю сеть с `vmnet-shared` на `virtio-net-pci`, чтобы пробрасывать порты,
когда не доступен ssh (like `-nic user,model=virtio-net-pci,hostfwd=tcp:127.0.0.1:2222-:2`)

Но такое решение отправить я не мог:
- drive.img весит слишком много (хотя это sparse и по факту он занимает меньше, чем в нём аллоцировано)
- по условию нужен kvm
- я предположил, что требуется x86_64 ВМ

Изначально была идея сделать Makefile, который бы скачал нужный .img из интернета,
собрал бы образ диска и что-нибудь бы там запустил, но мне показалось, что оно
того не стоит, поэтому я стал смотреть в сторону какого-то микро ОС образа,
размером < 50MB, чтобы его запихнуть в репу и всё запускалось без дополнительного
ожидания.

Сначала я хотел alpine, но почти сразу переключился на puppy os (это вот который
на флешки ставят), но случайно по запросу в гугле наткнулся на cirr os:
> CirrOS is a minimal, lightweight Linux distribution designed specifically as a test image for cloud computing platforms like OpenStack

Ну прямо то, что нужно)

## Итоговое решение

В первую очередь есть папка `images` - там лежит базовый образ cirr os, на
котором уже можно грузить ВМ. Он весит мало, поэтому я его просто закоммитил)

Если просто запустить на нём ВМ, она будет грузиться полчаса, потому что выполняет
какие-то стрёмные сетевые инициализации. У cirr есть механизм на подобе cloud-init,
можно подложить конфиги, чтобы что-то настроить, вот есть папка `seed`, где они
как раз и лежат - нужны, чтобы не ждать, пока настроится сеть.

Запихнуть конфиги из `seed` просто так в ВМ не выйдет, их нужно положить на
какой-нибудь диск. Разбирать исходную ФС мне было лень, потому что macOS, на
которой я работаю, не очень любит `mount .img dst/`. Поэтому генерируется
дополнительный iso файл через xorriso.

Как этим пользоваться - через `make`
Есть несколько целей для создания дисков и основная цель - `run` - для
запуска ВМ соответственно.

Для проверки достаточно запустить `make run`, диск (qcow который) создастся 
автоматически на основе образа cirr os, iso с настройками я закоммитил, чтобы
при проверке не требовалось скачивать xorriso, но если его удалить, make
попытается его создать.

Логин и пароль к ВМ `curros:gocubsgo`, выключить её потом можно через `sudo poweroff`
